## 결론 (정직한 판정)
- 수치만으로는 해소 불가: idle 0, cast .25까지 낮춰도 탭이 열림 창만으로 17~21초·사망 0으로 깬다. 탭 봇은 보스 곁에 붙어 있다가 매 열림에 치고, 기침·펄스에 맞아도 열림이 생겼기 때문.
- 메커니즘 추가(코드 반영): 기침 숨결·펄스에 실제로 맞으면 그 뒤 열림 없음(CT.BOSS_OPEN_IF_HIT=0). 효과: 탭 사망 0 -> 5.0, 처치 5/5 -> 2/5. 그러나 reader/window 봇도 회피를 못 해(봇 한계) 0/5 — 목표 "reader 처치율 >= 탭"은 봇 기준 미달성.
- 현재 코드값: BOSS_HP 1000 / IDLE 0.5 / OPEN 2.0 / CAST 1.25 / OPEN_IF_HIT 0. 사람은 봇보다 회피를 잘하므로 유리할 가능성이 크지만 사람 플레이 검증 필요. 봇 회피(기침 구르기) 개선 후 재측정이 다음 단계.
- 대안(디렉터 결정): 메커니즘 없이 HP1000/idle.75/open2.0 은 탭 3/3 27s vs reader 2/3 77s — 봇 기준 reader가 접근하나 탭 우위 유지.

## 최종 (2026-10-13 디렉터 확정: HP1000 / IDLE 0.5 / OPEN 2.0 / CAST 1.25 / OPEN_IF_HIT 0)
봇 회피 개선(tests/godot/balance_probe.gd): reader/window 가 기침 부채꼴(±0.75rad,135px) 안이면 조준선에서 옆걸음+숨결 직전 구르기, 펄스 시전 중 사거리 안이면 뒤로 구르기. 개선 후 판당 가상 사망: reader 5.2 -> 2.6, window 4.6 -> 2.2.
n=5, 한도 240초 (raw/boss_sweep_20261013.txt 의 cast=1.25 hp=1000 idle=0.5 3번째 블록):
| 정책 | 처치 | 시간 | 판당 사망 |
|---|---|---|---|
| 탭 | 4/5 | 23s | 1.8 |
| reader | 0/5 | - | 2.6 |
| window | 0/5 | - | 2.2 |
추가 시도(같은 봇): HP1000 idle .15 open 3.0 -> 탭 4/5 206s 사망7.4 / reader 0/5 2.4 / window 0/5 2.4; idle .25 open 2.5 -> 탭 1/5 125s 사망7.6 / reader 0/5 2.2.
- 해석: 탭 봇의 처치는 평시 피해(x0.5)를 붙어서 누적한 것으로 사망 1.8로 위험이 낮다. 평시 배율을 .15~.25 로 낮추면 탭은 사망 7+ 에 처치 느림/불가(불리)가 되나, reader/window 봇도 처치 못 함: 봇은 열림 창 전환(옆걸음 뒤 복귀 -> 강 베기)이 느리고 closing 규칙(붙은 지 1초 후 후퇴)으로 공격 시간이 적다. 즉 봇으로는 "reader 처치율 >= 탭"을 증명하지 못했다 — 한계. 사람 플레이 확인 필요.
- 권고(디렉터 판단용): IDLE 0.25~0.15 로 낮추면 탭 연타가 확실히 불리(사망 7배 이상)하다. 단 사람 reader 의 열림 창 처치가 확인되기 전에는 보스 불가 위험이 있어 확정 상수는 IDLE 0.5 유지.
- 보스가 사람에게 너무 어려워질 위험은 보스방 입구 부활(anchors.boss_respawn)로 완화된다: 사망해도 입구에서 즉시 재도전, 진행 손실 없음.

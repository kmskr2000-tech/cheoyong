## 1. Overview

플레이어가 "지금 뭘 하면 되지?"를 **한 눈에, 글을 안 읽어도 알게** 만든다. 세 층으로 쌓는다.

1. **목표 한 줄** — 화면 상단에 간결체 한 줄("집에서 쉰다"). 새 목표가 생기면 반짝였다가 가라앉는다. 설정에서 끌 수 있다.
2. **용패 빛(방향 마커)** — 이미 있는 "용패 길잡이"(바이블 2-5)를 **확장**한다. 새 방식을 들이지 않는다: 빛 조각을 더 눈에 띄게, 대상이 화면에 들어오면 대상 위에 가는 빛기둥, 가까우면 기존 "다가가면 버튼이 빛난다"(말하기 점등)로 인계.
3. **출구 열림 알림** — 길이 열리면 토스트 한 줄, 목표가 출구면 출구에 빔.

핵심 판단 두 가지.

- **글은 "목표"만 말하고 "조작"은 말하지 않는다.** "갯귀를 정화한다"(목표) O, "노래 버튼을 눌러라"(입력) X. 입력 안내는 지금처럼 버튼 점등이 한다 — CLAUDE.md BotW 원칙 유지.
- **상태 없는 계산.** 목표는 `Game.level_id` + `Game.flags` 만으로 매 순간 계산한다(지금 `Story.objective()` 방식 그대로). 세이브·이어하기·디버그 진입(`--level= --flags=`)이 따로 손대지 않아도 맞는다.

**이번 설계가 고치는 확정 결함**: 지금 `story.gd:737` 이 SC1-21(며칠 뒤) 이후 길잡이를 옛 좌표 (96,130) 로 보낸다. 집은 (130,237) 이다(`8b1d7b7` 커밋이 `night` 분기만 고치고 `rumor` 분기를 놓침). 이 구간은 **무엇을 해야 하는지 알 방법이 아예 없다.** 설계와 별개로 **한 줄 핫픽스를 먼저 내보낼 것을 권한다**(§9 P0).

## 2. Player Fantasy

- 길을 잃은 밤길에 용패가 손등에서 희미하게 따뜻해지고, 빛이 한 방향으로 흘러간다. 따라가면 사람이 나오고, 가까워지면 말을 걸 수 있다는 손짓(버튼 점등)이 온다. *"이끌린다"*(바이블 2-5)지, *"끌려간다"*가 아니다.
- 읽지 않아도 된다. 상단의 한 줄은 헤맨 사람을 위한 보험이고, 잘 가는 사람에게는 흐릿한 배경이다.
- 연출 장면에서는 아무것도 뜨지 않는다. 노래·춤·침묵이 주인공일 때 UI 가 끼어들지 않는다.

## 3. Detailed Rules

### 3.1 목표 정의 (데이터)

목표 하나 = `{id, text, target, kind, via, show}`.

| 필드 | 의미 |
|---|---|
| `id` | `ch1.<레벨>.<이름>` (표 §3 의 상태 ID). 로그·테스트 키 |
| `text` | 목표 문구. 빈 문자열이면 문구만 숨김(마커는 유지) |
| `target` | 마커가 향할 곳. footprint 좌표 `Vector2`, 또는 움직이는 대상이면 `Node2D`(NPC·갯귀). `null` = 마커 없음 |
| `kind` | `npc` · `interact` · `exit` · `node` · `area` · `none` |
| `via` | 직선이 막힐 때 먼저 향할 지점 배열(선택). 빈 배열이면 직선 |
| `show` | `text` 노출 정책 override(`"fallback"` = 20초 폴백만, 기본 `"normal"`) |

- 조건 평가는 **위에서 아래로 처음 맞는 행**(현재 `objective()` 의 `match`/`if` 순서 그대로 이관).
- 현재 상태 한 개만 존재한다(퀘스트 로그 없음). 선택 활동(약방·잡담·게시판)은 목표에 오르지 않는다 — 단, 그 대상 근처에 가면 기존 말하기 점등이 켜진다.

### 3.2 문구 규칙

1. UI 문구는 **간결체**(`~한다`, 명사형). 시대극 말투(~하오/~소/~오)는 **대사에만** 쓴다.
2. **공백 포함 18자 이하.** 이유: 480×270, 폰트 Galmuri11 12px(전각 12px 폭), 사용 폭 308px 이내 + 안전 여유(§5.1).
3. **목표를 말하고 입력을 말하지 않는다.** "버튼", "누른다", "터치" 금지.
4. 이름은 플레이어가 **이미 알게 된 뒤에만** 쓴다(금칙어 규칙 §3.3).
5. 한 문구에 동사 하나. 이동 목표 + 행동 목표를 이어 쓰는 경우는 다른 레벨 이동뿐("관아를 나서 폐가로 간다").

### 3.3 스포일러 금칙어 (전 문구에 적용 — 표의 금칙어 열이 이 규칙의 장면별 적용)

| 금칙어 | 허용 시점 |
|---|---|
| 난영 | `met_nanyeong` 이후 (첫 대화 전엔 "약방") |
| 아내 | 혼례 몽타주(`married`) 이후 — 사실상 목표 문구에 쓰지 않음 |
| 역신 | SC1-15 대화(`inner` 트리거) 이후 |
| 넋 | 쓰지 않음(1장 문구 전체에서 금지: SC1-15 에서 처음 명시되는 설정) |
| 왕, 입궐, 어명 | SC1-22 내관 대사(`king_call`) 이후 |
| 퇴마어사, 어사 | `appointed` 이후 (1장 문구엔 사실상 쓰지 않음) |
| "왕이… 오신다" | **어떤 문구에도 금지** (SC1-19 유언의 복선) |
| 2장 어휘(도깨비, 지리산, 두억시니…) | 1장 문구에 금지 |

### 3.4 방향 마커 방식 비교와 추천

비교 기준: 바이블 정합 · BotW식 최소 UI · 480×270 가독성 · HUD_LAYOUT 간섭 · 출구/NPC/적 모두 커버 · 구현 비용.

| 안 | 설명 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| A. 화면 가장자리 화살표 | 대상이 화면 밖일 때 가장자리에 ▶ | 먼 거리에서도 정확한 방향 | **오른쪽 아래 버튼 7개(x≈346–476, y≈128–266)와 왼쪽 플로팅 조이스틱 영역이 가장자리를 이미 차지** → 화살표가 버튼과 겹치거나 가려져야 함. 상시 HUD 요소가 하나 더 생김("빛나는 버튼 하나" 원칙과 충돌). 바이블 2-5 의 "희미하게 빛난다"와 이질적 | 제외 |
| B. 용패 빛 조각(기존) 확장 | 가슴에서 대상 쪽으로 흐르는 빛 + 대상 위 빛기둥 + 출구 빔 | **바이블 2-5 에 이미 명시된 장치.** 세계 안(diegetic)이라 HUD 자리를 안 먹음(hud_layout 영향 0). 출구·NPC·요괴 모두 같은 언어로 표현. 이미 구현돼 있어 증분 비용 작음 | 직선이라 벽 너머를 가리킬 수 있음 → `via` 경유점으로 보완. 5px 점이 작음 → 개수·크기·대상 빔으로 보강 | **추천** |
| C. NPC 머리 위 아이콘(느낌표) | 대상 NPC 위에 `!` | 관례적이라 즉시 이해 | NPC 에게만 적용(출구·아이템·요괴 불가) → 두 번째 장치 필요. 아이콘 종류별 아트 필요. 모든 NPC 에 붙으면 과장, 목표 NPC 에만 붙이면 B 의 대상 빔과 역할 중복. BotW 최소주의와 거리가 멀다 | 제외 |
| D. 길 위 점선 경로 | 지면에 이어지는 경로 | 막힌 길도 정확 | 경로 계산·렌더 비용, 화면 어지러움, 바이블과 이질적 | 제외 |

**추천 = B 확장 ("용패 빛")**, 세 구간으로 동작한다.

| 구간 | 조건(플레이어-대상 거리 d) | 보이는 것 |
|---|---|---|
| 먼 길 | d ≥ 240px(화면 밖일 확률 높음) | 빛 조각 3개가 시차를 두고 흐름, 더 크고(7px) 더 밝음(알파 0.95) |
| 가까운 길 | 32 < d < 240 | 빛 조각 3개(5px, 알파 0.8) + **대상이 카메라에 보이면 대상 위에 빛기둥(beacon)** |
| 인계 | d ≤ 32 (= `TALK_RANGE 26` + 6 여유) | 빛 조각·빛기둥 사라짐 → **말하기 점등이 이어받음**(NPC·상호작용) / 출구는 그대로 밟으면 이동 |

현재는 40px 안에서 사라지는데 말하기 점등은 26px 부터라 **26~40px 에 아무 안내도 없는 빈 구간**이 있다. 인계 거리를 32px 로 맞춰 없앤다(빛 조각 숨김과 말하기 점등 사이 6px 겹침은 의도).

### 3.5 방향 마커 세부

**빛 조각(기존 `_guide` 확장)**

- 현재: 5×5px 1개, 10→32px 흐름, 주기 1.6s, 최대 알파 0.8, `ADD` 블렌드, z 45, 숨김 조건 `d<40 ∨ Player.locked`.
- 변경: 같은 텍스처로 **3개**(위상 1/3 주기 어긋남), 먼 길이면 스케일 1.4·알파 0.95, 이동 반경 `12 → 12 + clamp((d-32)/12, 0, 34)` px. `via` 가 있으면 현재 `via[0]` 가 목표이고, 거기서 32px 이내가 되면 다음 `via` 또는 `target`.
- 숨김 조건: `d ≤ 32` ∨ `Player.locked` ∨ 설정 "길잡이 빛: 끔".

**빛기둥(beacon, 신규)**

- 대상이 **카메라 시야 안**(`abs(dx)<240 ∧ abs(dy)<135`, 시야는 480×270)일 때만. 3×22px 세로 그라데이션, 같은 색(0.8,0.95,1.0), `ADD`, 알파 `0.35 + 0.35·sin(2π·t/1.4)`.
- 위치: NPC 는 머리 위 30px, 상호작용 지점은 위 18px, 출구는 사각형 중심 위 18px, 요괴 노드는 머리 위 34px.
- 대상 32px 안이면 0.25초 페이드아웃. 모든 대상 종류에 **같은 모양** — 아이콘이 아니라 빛이다.
- 목표가 아닌 NPC/출구에는 절대 붙지 않는다(한 번에 하나).

**출구 빔**: `kind == exit` 의 빛기둥은 사각형 폭에 맞춰 가로로 넓힌다(`min(rect.w, 48)`px). 출구가 "목표일 때만" 표시한다. 출구가 열리는 순간 토스트도 띄운다(§3.7).

### 3.6 목표 문구 표시 (HUD)

- 위치·크기: 상단 중앙 띠 `Rect2(136, 3, 308, 14)`, 가운데 정렬, Galmuri11 12px, 외곽선 4(토스트와 같은 처리), 색 진주빛 `Color(0.93, 0.90, 0.78)`. 앞에 `◇ ` 한 글자(폰트 글리프, 아트 불필요).
- 이유(상단 띠): 우하단 버튼 영역·좌하단 조이스틱·하단 대화창(`Rect2(20,188,440,74)`)·좌상단 상태 영역(x6–126)·메뉴 버튼(450–474,4–28)·토스트(y54–74)를 전부 피하는 유일한 가로 띠.
- 노출 모드(설정 `obj_text`): **항상**(기본) / **잠깐** / **끔**.
  - 항상: 알파 0.75 상시. 새 목표가 생기면 1.5초 동안 알파 1.0 + 1회 밝은 번쩍임.
  - 잠깐: 새 목표 때 5초 노출 후 페이드, 이후 **무입력 25초**가 되면 4초 재노출.
  - 끔: 문구 없음. 빛(방향)은 별도 설정.
- 설정 `obj_light`(길잡이 빛 켜짐/끔, 기본 켜짐). 저장은 `Game.set_setting` → `user://settings.json`(세이브와 분리, 이미 있는 경로). 새 `TouchScreenButton` 은 만들지 않는다(`hud_layout.gd` h0 가 터치 버튼 7개를 단정). 설정 UI 는 행낭(일시정지) 메뉴에 항목 추가.

### 3.7 갱신·완료 타이밍

- **계산**: `Story.objective_info(level)` 를 0.25초마다 + `Game.progress_changed` + 레벨 진입 시 호출(상태 없는 순수 계산, 배열 몇 개 비교라 비용 무시).
- **표시 확정 조건**: `!Player.locked ∧ level._talking == 0 ∧ !Game._busy ∧ 카드/페이드 없음`. 조건이 풀리면 바뀐 목표를 **대기**시켰다가 조작이 돌아오는 순간 적용 — 연출 도중 문구가 튀지 않는다.
- **새 목표 표시**: 이전 문구 0.25s 페이드아웃 → 새 문구 0.25s 페이드인 + 밝은 번쩍임 → 가라앉음. 효과음은 기존 `Audio.sfx("pickup", -18)`(아주 작게, 신규 사운드 없이도 가능. 전용 차임은 선택 §9 P6).
- **완료**: 별도 "완료!" 토스트 없음 — 목표가 다음 상태로 바뀌는 것이 완료 표시다(소음 최소). 단 **길이 열릴 때만** 토스트: "관아로 가는 길이 열렸다." / "서쪽 길이 열렸다.".
- **폴백(R-폴백)**: 문구가 의도적으로 없는 상태(E-1: SC1-01 시작)에서 조작 가능 상태로 **20초 무입력**이면 폴백 문구를 5초 노출("반짝이는 것을 줍는다"). 바이블 "무음"은 연출 3초 구간까지만 유효하다고 해석.
- **숨김(R-숨김)** — 목표 문구와 빛기둥을 숨기는 상황: `hud._guide != ""`(튜토리얼 점등 중, "빛나는 버튼 하나" 원칙) / 보스 체력바 표시 중 / 연출·대화·카드·페이드 / 일시정지. 빛 조각은 `Player.locked` 에서만 숨김(전투 중에도 흐름 — 현재 동작 유지).

### 3.8 API 구조 (구현 지침)

- `Story.objective_info(level) -> Dictionary` 신설: `{id, text, target, kind, via, show}`. 기존 `Story.objective(level)` 는 **래퍼로 유지**: `objective_info(level).get("target")` 를 footprint `Vector2`/`null` 로 변환해 반환. → `level._update_guide` 와 **2장 분기(hwagae~den3)는 수정 없이 동작**(2장 `text` 는 빈 문자열 = 문구 숨김, 마커는 지금과 동일).
- 1장 데이터는 코드가 아니라 **표(`objective-marker-table.md` §3)와 1:1** 로 옮긴다. 상태 ID 는 표와 같게.
- 움직이는 대상(`npc`, `node`)은 `level.npc(id)` / 노드 참조로 위치를 읽는다(밤에 난영이 `home_nanyeong` 으로 옮겨지는 경우 포함 — 하드코딩 좌표 금지). NPC 가 비표시(`set_present(false)`)면 같은 행의 `fallback` 좌표를 쓴다.

## 4. Formulas

기호: `d` = 플레이어 발밑과 대상(footprint→`lift`)의 거리(px). `T_talk = 26`(`level.gd:TALK_RANGE`).

| 항목 | 식 / 값 | 근거·범위 |
|---|---|---|
| 인계 거리 | `H = T_talk + 6 = 32` | 말하기 점등 시작(26)보다 6px 크게 → 빈 구간 제거. 안전 범위 28~40 |
| 빛 조각 반경 | `r(d) = 12 + clamp((d − 32) / 12, 0, 34)` px | d=32→12px, d=440 이상→46px(상한). 예: d=121 → 12+7.4=19.4px |
| 빛 조각 알파 | `d ≥ 240` → 0.95 · 그 외 0.8 | 먼 길만 강조 |
| 빛 조각 스케일 | `d ≥ 240` → 1.4 · 그 외 1.0 | 5px→7px |
| 빛기둥 시야 | `abs(dx) < 240 ∧ abs(dy) < 135` | 480×270 절반. 카메라 오프셋 연출 중에는 `Camera2D.global_position` 기준 |
| 빛기둥 알파 | `0.35 + 0.35·sin(2π·t/1.4)` | 0~1 범위 안 |
| 문구 최대 길이 | 공백 포함 **18자** | 12px 전각 ≈ 216px ≤ 사용폭 308px (여유 92px = 언어 변형/폰트 차이 흡수) |
| 문구 폴백 | 조작 가능 상태 무입력 **20초** → 5초 노출 | 안전 범위 15~30초 |
| 잠깐 모드 재노출 | 무입력 **25초** → 4초 | 안전 범위 20~40초 |
| 목표 평가 주기 | **0.25초** | `Game.progress_changed`·레벨 진입 시 즉시 |
| 문구 페이드 | 아웃 0.25s · 인 0.25s · 번쩍임 1.5s | |

**예시 계산** — SC1-11 밤, 집 스폰 (140,245) → 관아 문 (562,28): `d ≈ 475` → 먼 길(알파 0.95, 7px, `r=46`). 대상이 시야 밖이라 빛기둥 없음 → 빛 조각이 북동쪽으로 길게 흐른다. 반쯤 가 `d ≈ 230` → 가까운 길, 대상이 시야 안에 들어오면 문 위 18px 에 빛기둥이 켜진다. `d ≤ 32` → 모두 사라지고 문을 밟으면 이동.

## 5. Edge Cases

각 항목은 "무엇이 일어난다"를 명시한다.

1. **터치 UI 간섭**: 문구 띠는 `Rect2(136,3,308,14)`. 좌상단 상태(~x126)와 10px, 메뉴 버튼(x450~)과 6px(`SAFE`) 이상 이격. 빛 조각·빛기둥은 월드 노드라 `hud_layout.gd` 의 터치 반경·버튼 그림 겹침 검사 대상 밖. **새 TouchScreenButton 추가 금지**(h0 = 7개).
2. **480×270 가독성**: 폰트 12px, 외곽선 4, 알파 0.75 상시. 밝은 낮 지형 위(경주 변두리 dusk)에서도 외곽선으로 읽힘 — 구현 시 `--capture` 로 5개 레벨에서 스크린샷 확인(§8 T7).
3. **보스전 중**: 보스 체력바(상단 중앙 y14~42)와 겹치므로 문구 숨김. 체력바가 사라지면(`defeated`) 문구 복귀 여부는 상태 없는 평가가 결정(보스 사망 후는 연출이라 어차피 숨김).
4. **튜토리얼 점등 중**(`hud.guide` 켜짐: SC1-05 구르기·SC1-19 노래): 문구·빛기둥 숨김, 빛 조각은 흐름 유지(갯귀 쪽). 점등이 꺼지면 문구 복귀.
5. **사망·리스폰**: 평가는 상태 없음이라 입구에서 일어난 뒤 같은 목표가 즉시 복귀. 보스방은 `ch1.pyega2.after_death`.
6. **이어하기·세이브**: 플래그에서 재계산 → 별도 저장 필요 없음. 세이브 형식 변경 없음.
7. **디버그 진입**(`--level=gyeongju` 플래그 없음): `!met_nanyeong` 조건이 맞아 `apothecary` 가 뜬다. 모든 레벨은 "플래그 전부 없음" 상태에서도 문구가 비지 않아야 한다(T1).
8. **플래그가 지워지는 경우**: `Game.flags.erase("night")`(SC1-20·SC1-23 후) → `night` 가 사라지면 `rumor` 분기가 먼저 평가돼야 한다. 평가 순서가 곧 우선순위(표 §3.3 순서 유지).
9. **대상 NPC 가 숨음/이동**: 비표시이면 `fallback` 좌표. 밤 난영 = `anchors.home_nanyeong`.
10. **대상이 막힌 곳/벽 너머**: `via` 로 우회. `via` 가 `미검증` 인 행은 T2 가 통과해야 구현 완료 인정.
11. **대사 중 목표가 바뀌는 경우**(예: 형방 대화 중 `briefed` 세팅): 표시 확정 조건이 풀릴 때까지 대기 후 적용.
12. **여러 플래그가 동시에 참**: 위→아래 첫 행만 채택(현재 `objective()` 와 동일).
13. **`chapter1_done`**: 문구 없음(E-5). 빛 조각도 없음(`target = null`).
14. **문구 없음 + 대상 있음**: 마커만 표시(E-1·E-2). **문구 있음 + 대상 없음**: 문구만(예: 보스 입장 직전 연출 후 첫 순간).
15. **긴 문구**(18자 초과): 테스트가 실패시킨다. 폴백으로 줄여 쓰지 않음.
16. **설정 "끔"**: 문구도 빛기둥도 없음. 빛 조각은 `obj_light` 에 따름. 빛 조각까지 끄면 말하기·노래 점등만 남는다(기존 동작).
17. **경주 서쪽 길 `gates.pyega`**: `night ∧ briefed ∧ !rescued` 에서만 열림. 열리기 전에 서쪽 끝에 가면 벽 → 선택 기능으로 토스트 "아직 갈 때가 아니다."(§9 P8).
